# Release roadmap

The long-term goal is a large original MMORPG. First complete an enjoyable smaller release, then expand its content and online capacity. These are targets, not shipped-content claims.

| First-release target | Scope |
|---|---|
| Classes | Three distinct weapon identities, at least four meaningful active skills each |
| World | One detailed town, three connected wilderness regions, two dungeons |
| Combat | Twelve meaningfully different enemies and three bosses |
| Quests | Fifteen authored quests, including a main chain with an ending |
| Progression | Inventory, visible equipment, loot qualities, merchants, gathering, crafting, upgrades and persistence |
| Companions and mounts | Three original companions and two mounts |
| Multiplayer | Tested server authority with independent two-to-four-player clients |
| Delivery | Tested Windows package, onboarding, settings, credits and play/hosting instructions |

## Current milestone

The private merchant progression slice now has actual fresh-character quest/combat/loot, delayed manual revive, visible weapon changes, merchant transactions and cold-reopen proof in a packaged Windows Development build. Separate editor-standalone testing covered earned full-bag failure cases and retained-loot recovery. V3 journal and frozen migration source is now independently qualified by five public portable suites, a fresh public editor-module compile and four memory-only codec tests. See [validation](VALIDATION.md) for the boundaries.

The public source milestone is complete at those selected checks; retain reproducible verification as the source changes. The next playable milestone is an original character and one fully visible persisted torso slot. The public host remains distinct from the private playable package, and asset/provenance publication remains separate.

## Next playable milestones

Continue original character work from the saved body, facial keys, rig and garment studies. Compare matched front/profile renders with the original concept before changing anatomy. Improve the hair's local flow, part and ear framing while preserving unrelated geometry. Current character, outfit and interface art remain unaccepted; studies and proprietary reference images are excluded from this repository.

Complete one visible persisted torso slot using a covered base outfit and an original reinforced tunic. The current provisional SKU and V3 representation are not proof of a qualified mesh, full armor swapping, animation fit or recovery after revival. Then extend distinct class skills, enemy behavior and purposeful regions; add mining, another gathering activity, recipes, upgrades, conversations, companions, mounts and dungeons. A fresh character must reach the main quest ending.

Qualify independent two/four-client interactions, reward ownership, combat/death, disconnect/reconnect, durable progression and failure recovery in a separate development scope. Keep client requests as intents and validate currency, item creation, cooldowns, range and damage on authority. Session resume tickets are not production authentication.

Measure traversal/combat, loading and sustained memory on the development PC and repeat packaged regression checks as content grows. Complete onboarding, controls/settings, accessibility, sound, credits/provenance and useful error handling. A local packaged prototype is one milestone toward v1, not release completion.

Larger online capacity separately requires account identity, durable character ownership, party/social systems, migrations/backups and restore drills, measured server/zone capacity, load/soak tests, moderation, abuse prevention, hosting and operations. A small local server is not MMO-scale readiness. Public hosting, paid services, credentials and deployment remain separate decisions.
